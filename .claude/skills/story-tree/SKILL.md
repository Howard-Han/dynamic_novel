# 製作劇情樹狀圖

對應 `.claude/rules/writing_details.md` 的寫作步驟 2~3。執行前必須先通過 `/novel-precheck` 檢查，並讀過該小說的所有設定檔。

## 結構規範：DAG＋狀態旗標

- 劇情圖採**有向無環圖（DAG）**：允許不同路徑合流至同一篇章節點，避免相同劇情複製多份節點。
- 由前置選擇決定、且影響後續分岐或結局判定的狀態，定義為**狀態旗標**（flag），例如：「已暗殺韓德爾」「愛戴兒同行」。
- 每個結局節點需標明其判定所需的旗標組合，且該組合必須與 結局設定.md 的必要要素一致。
- 旗標清單要一併記錄（名稱、由哪個篇章的哪個選項設定、影響哪些分岐/結局），之後網站 JS 引擎將依此實作 flag 機制。

## 製作步驟

1. 將各篇章當作節點，設計每個篇章的編號與標題；前/中/後段的篇章需涵蓋 必要要素設定.md 中對應段落的要素。
2. 將各結局當作路徑最後的節點，**確保從初始篇章開始走都能走到任一個結局**。
3. 設計每個篇章結尾的選擇題與選項，確保每個選項與所連結的下個篇章（或結局）內容合理且無劇情衝突。
4. 留意 結局設定.md 中的「最低篇章數」限制（若有），確認所有能進到該結局的路徑篇章數足夠。
5. 標示「劇情解鎖」要素只在特定篇章之後才提及。

## 呈現與定案

- 以 Mermaid flowchart 呈現：節點＝篇章編號＋標題，邊＝選項摘要，需要時在邊或節點上標註旗標的設定與判定。
- 與使用者討論是否調整；定案後將劇情圖與旗標清單存檔至該小說資料夾內的 `劇情樹狀圖.md`。
- 定案前可用 story-validator agent 做獨立審查。
